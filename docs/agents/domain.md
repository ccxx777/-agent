# Domain Docs（领域文档）

本项目采用 single-context（单一领域上下文）布局。

## 开始理解代码前

如果以下内容存在，应先阅读与当前任务相关的部分：

- 根目录 `CONTEXT.md`
- `docs/adr/` 中相关的 ADR

文件不存在时直接继续，不需要提前创建空文件。领域术语和架构决策在真正确定后再由相应流程补充。

## 目录约定

```text
/
├── CONTEXT.md
├── docs/
│   └── adr/
└── ...
```

`CONTEXT.md` 用于记录领域边界、核心术语和业务不变量。

`docs/adr/` 用于记录重要且长期有效的架构决策，例如合同审查 Workflow、法律证据等级和用户数据隔离方式。

## 术语一致性

Issue、重构方案、测试名称和代码命名应优先使用 `CONTEXT.md` 中已经定义的领域词汇。

如果所需概念尚未定义，应先判断：

1. 是否只是创建了没有必要的新同义词；
2. 是否确实发现了需要补充的领域概念。

## ADR 冲突

如果计划与已有 ADR 冲突，必须明确指出冲突，不能静默覆盖原有决策。
