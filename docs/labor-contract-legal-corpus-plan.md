# 劳动合同法律知识库采集计划与执行清单

> 文档状态：首版采集计划
>
> 更新时间：2026-07-30
>
> 适用范围：中国大陆、全国通用规则、个人用户劳动合同签署前辅助审查

## 一、先说结论：现在不需要收集“所有法律”

首版不需要一次性建立完整的劳动法数据库，也不需要先搜集大量裁判文书。为了让合同审查 Workflow 形成一个可验证的闭环，第一批资料建议控制为：

| 资料 | 首批数量 | 目的 | 优先级 |
|---|---:|---|---|
| A 级法律、行政法规、司法解释 | 8～12 份 | 作为主要法律依据 | P0 |
| B 级最高人民法院官方案例 | 10～15 个 | 用于补充解释，不作为首要依据 | P1 |
| 结构化规则卡片 | 10～20 条 | 让 Workflow 做确定性判断 | P0 |
| 脱敏合同测试样本 | 5～10 份 | 验证事实提取、确认和报告 | P0 |
| 检索问题集 | 15～30 题 | 验证法律检索和引用 | P0 |

这里的“人工收集”是知识库建设阶段的资料整理，不是让产品用户手动上传法律文件。后续可以再增加法律资料管理后台或批量导入脚本。

## 二、资料分层与产品边界

首版必须保持以下边界：

1. **A 级优先**：现行有效的全国性法律、行政法规、司法解释和官方规范性文件。
2. **B 级补充**：最高人民法院指导案例、典型案例和官方可核验的裁判资料。
3. **暂不接入**：律师公众号、转载文章、来源不明的案例摘要、付费访问内容和授权不明确的网页。
4. **暂不做地方判断**：不把各省市最低工资、地方裁审口径或地方性规定混入全国通用规则。遇到需要所在地信息的事项，Workflow 应输出“需要补充地区信息”或“首版不作地方判断”。
5. **不把案例当成法律条文**：案例只能解释事实类型和裁判思路，不能替代 A 级法律依据。

## 三、第一批必须收集的 A 级资料

### 3.1 核心法律（P0）

这些文件直接覆盖劳动合同的订立、履行、解除、争议和社会保险基础问题：

- [ ] 《中华人民共和国劳动合同法》
  - 重点覆盖：合同必备事项、合同期限、试用期、变更、解除/终止、经济补偿、违约金、竞业限制、劳务派遣。
  - 官方来源建议：人力资源和社会保障部法规页面。
  - [官方全文](https://www.mohrss.gov.cn/xxgk2020/fdzdgknr/zcfg/fl/202011/t20201102_394622.html)
- [ ] 《中华人民共和国劳动合同法实施条例》
  - 重点覆盖：劳动合同法中需要具体解释和执行的事项。
  - [国家行政法规库](https://xzfg.moj.gov.cn/mobile/law/detail?LawID=284)
- [ ] 《中华人民共和国劳动法》
  - 重点覆盖：工作时间、休息休假、工资、劳动保护和劳动关系基本原则。
  - [中国政府网全文](https://www.gov.cn/banshi/2005-05/25/content_905.htm)
- [ ] 《中华人民共和国劳动争议调解仲裁法》
  - 重点覆盖：争议范围、举证、调解、仲裁和诉讼衔接。
  - [中国人大网全文](https://www.npc.gov.cn/WZWSREL3pncmR3L25wYy8vLy94aW53ZW4vbGZnei96eGZsLzIwMDctMTIvMjkvY29udGVudF8xMzg3ODA5Lmh0bQ%3D%3D)
- [ ] 《中华人民共和国社会保险法》
  - 重点覆盖：社会保险缴纳、保险关系和基本待遇相关事实。
  - [中国人大网全文](https://www.npc.gov.cn/zgrdw/npc/xinwen/2019-01/07/content_2070267.htm)

### 3.2 最高人民法院司法解释（P0）

- [ ] 《最高人民法院关于审理劳动争议案件适用法律问题的解释（一）》
  - [最高人民法院全文](https://www.court.gov.cn/zixun/xiangqing/282121.html)
- [ ] 《最高人民法院关于审理劳动争议案件适用法律问题的解释（二）》
  - [最高人民法院公报全文](https://gongbao.court.gov.cn/Details/bb72019c45453f84d920bd6375573e.html)
  - 该解释自 2025 年 9 月 1 日起施行；采集时必须同时记录施行日期、与解释（一）的衔接关系以及被废止或调整的条款，不能只保存一份旧版解释。

### 3.3 与首版审查主题直接相关的行政法规和部门规章（P0/P1）

先收集与合同文本高频字段直接相关的资料：

- [ ] 《最低工资规定》——用于识别工资字段需要结合工作地区判断的情况；首版不内置地方金额。
- [ ] 《工资支付暂行规定》——用于工资支付、扣减和发放约定的基础核对。
- [ ] 《工伤保险条例》——合同涉及工伤、职业伤害或相关责任表述时使用。
- [ ] 《职工带薪年休假条例》及《企业职工带薪年休假实施办法》——合同包含休假、年假约定时使用。
  - [国家法律法规数据库条目](https://flk.npc.gov.cn/detail?id=ff8080816f3e98bd016f420b9b460371&title=%E8%81%8C%E5%B7%A5%E5%B8%A6%E8%96%AA%E5%B9%B4%E4%BC%91%E5%81%87%E6%9D%A1%E4%BE%8B)
- [ ] 《女职工劳动保护特别规定》——只有当合同事实涉及孕期、产期、哺乳期或特殊岗位时触发。
  - [国家行政法规库](https://xzfg.moj.gov.cn/mobile/law/detail?LawID=343)
- [ ] 《劳务派遣暂行规定》——只在识别为劳务派遣合同或用户明确选择该场景时加载。

这些资料不应全部无条件塞进同一次检索。Workflow 应先根据合同类型和已确认事实选择适用主题，再检索对应的法律子集。

## 四、B 级案例应当收集什么

第一批不追求数量，按下面的争议主题各收集 1～3 个官方案例即可：

- [ ] 未签订书面劳动合同或劳动关系认定
- [ ] 试用期约定、试用期解除和试用期工资
- [ ] 合同期限、无固定期限劳动合同
- [ ] 工资、绩效、加班和工资扣减
- [ ] 社会保险缴纳或未缴纳
- [ ] 违法解除、经济补偿和赔偿
- [ ] 竞业限制和保密条款
- [ ] 违约金、培训服务期和限制性条款
- [ ] 劳务派遣（如果首版合同类型识别已经支持）
- [ ] 女职工特殊保护、工伤或职业伤害（按需扩展）

每个案例至少保存：

| 字段 | 要求 |
|---|---|
| `case_id` | 指导案例编号、案号或官方案例编号 |
| `title` | 官方标题，不自行改写成结论 |
| `court` | 审理法院或发布机关 |
| `published_at` | 发布或裁判日期 |
| `source_url` | 官方可访问地址 |
| `dispute_type` | 争议主题 |
| `facts_summary` | 脱敏后的事实摘要 |
| `holding_summary` | 裁判处理结果摘要 |
| `applicable_scope` | 可以类比的范围与不能直接类比的范围 |
| `source_level` | 固定为 `B` |
| `pii_status` | 是否已脱敏 |
| `review_status` | 待复核、已复核、退回 |

不要直接把整批互联网裁判文书放入知识库。案例应经过来源核验、个人信息检查和人工摘要，避免把单个案件的特殊事实误当成普遍规则。

## 五、必须建立的结构化规则卡片

法律原文解决“依据是什么”，规则卡片解决“在什么事实下触发什么审查”。首版规则不由模型自由生成，先由人工维护、版本化和测试。

每条规则至少包含：

```json
{
  "rule_id": "labor_contract.probation.term_consistency.v1",
  "domain": "labor_contract",
  "title": "合同期限与试用期一致性核对",
  "scope": "全国通用规则",
  "required_facts": ["contract_term", "probation_period"],
  "trigger": "已确认的合同期限与试用期同时存在",
  "conditions": [],
  "exceptions": [],
  "risk_level": "medium",
  "legal_references": ["labor_contract_law:article_xx"],
  "case_references": [],
  "evidence_required": ["contract_term", "probation_period"],
  "user_questions": [],
  "recommendation_template": "建议核对合同期限与试用期约定是否匹配",
  "rule_version": "2026-07-30",
  "review_status": "draft",
  "reviewer": null
}
```

第一批规则建议覆盖：

- [ ] 合同主体是否完整
- [ ] 合同期限是否缺失或表达不清
- [ ] 试用期是否缺失、重复或与期限事实冲突
- [ ] 工作地点、岗位和报酬是否存在关键缺项
- [ ] 工资是否只写“面议”或缺少可核对信息
- [ ] 工时、休息休假约定是否缺失或表述含糊
- [ ] 社会保险约定是否缺失或出现“由劳动者自行承担”等待核验表述
- [ ] 解除、终止和通知条款是否需要进一步确认
- [ ] 违约金、培训服务期和竞业限制是否触发专项审查
- [ ] 是否疑似劳务派遣、实习或劳务关系，超出劳动合同首版范围

注意：这里的规则卡片是工程输入，不是法律意见。每条规则在进入生产前都应有法律来源、人工复核记录、测试样例和失效日期。

## 六、测试资料也要准备

没有测试合同，Workflow 只能证明“能运行”，不能证明“判断正确”。建议准备三类测试资料：

### 6.1 法律检索问题集

先准备 15～30 个固定问题，每个问题绑定：

- 问题文本；
- 预期法律文档 ID；
- 预期条款号或段落；
- 允许的 A 级来源；
- 是否需要 B 级案例补充；
- 不应命中的地方性资料。

### 6.2 事实提取样本

准备 5～10 份脱敏劳动合同或自拟合同片段，覆盖：

- 字段完整的正常合同；
- 缺少工资、期限或工作地点的合同；
- 试用期和合同期限表达冲突的合同；
- 只写“按公司制度执行”的模糊条款；
- 含有竞业、培训服务期或违约金的合同；
- 疑似劳务派遣或非劳动合同文本。

### 6.3 端到端报告样本

至少为 3 份合同准备人工参考结果：

- 事实是否正确提取；
- 哪些事实需要用户确认；
- 哪些风险只能标记为“待核实”；
- 适用的法律来源；
- 风险等级是否合理；
- 修改建议是否保持中性，是否错误地替用户决定签署。

真实用户合同不应进入 Git、公开评测结果或共享截图。测试样本必须脱敏或由人工编造。

## 七、文件和目录应该怎么放

### 7.1 本报告的位置

本报告应放在：

```text
docs/labor-contract-legal-corpus-plan.md
```

它是项目设计和执行说明，可以提交到 GitHub/Gitee。

### 7.2 真实法律资料的位置

法律原文和案例属于本地数据，放在 Git 忽略的 `data/` 目录，不提交到公开仓库：

```text
data/
└── legal/
    └── labor_contract/
        ├── raw/
        │   ├── a_level/          # 法律、行政法规、司法解释、规章原文
        │   └── b_level/          # 官方案例原文或官方页面存档
        ├── normalized/            # 统一编码、清理后的 Markdown/JSONL
        ├── metadata/              # 来源、版本、生效状态、哈希、授权记录
        ├── rules/                 # 结构化规则卡片和人工复核记录
        ├── eval/                  # 检索问题、脱敏合同和参考报告
        └── manifests/             # 清单、校验结果和导入批次记录
```

法律资料建议至少分成两个 Qdrant collection：

```text
legal_labor_a_v1       # A 级法律优先检索
legal_labor_b_v1       # B 级案例按需补充
```

不要写入以下 collection：

- `rag_chunks`：现有通用生产语料；
- `watsonx_docsqa_colab_v1/v2`：离线评测语料；
- 用户合同专属 collection：合同原文和脱敏结果必须保持私有边界。

## 八、每份资料入库前的核验清单

### 8.1 来源和版本

- [ ] 来源是中国人大、国务院、最高人民法院、司法部、人力资源和社会保障部等官方渠道。
- [ ] 保存原始 URL、下载日期和页面标题。
- [ ] 记录制定机关、文号、公布日期、施行日期、修订日期。
- [ ] 检查现行有效、部分废止、全部废止或被替代状态。
- [ ] 同名文件不能只靠文件名判断版本，必须记录内容哈希。
- [ ] 司法解释和行政法规要保留历史沿革信息，避免旧版本覆盖新版本。

### 8.2 文本质量

- [ ] 文件编码统一为 UTF-8。
- [ ] 条、款、项编号没有丢失。
- [ ] 表格、脚注、附录和链接没有被解析器静默删除。
- [ ] PDF 有文本层时优先使用文本解析；扫描件 OCR 结果必须人工抽查。
- [ ] 原文、清洗文本和切分结果分别保留，不能只保留最终 chunk。

### 8.3 隐私与授权

- [ ] 案例中的姓名、身份证号、地址、电话等个人信息已经脱敏。
- [ ] 不采集律师公众号、付费数据库或授权不明确的转载内容。
- [ ] 每个文档记录 `license_status`、`pii_status` 和 `review_status`。
- [ ] 公开报告只引用文档标题、条款和官方链接，不展示真实个人信息。

## 九、推荐的实际执行顺序

### 第一步：先收集 P0 最小包

先完成以下 7 份：

1. 劳动合同法；
2. 劳动合同法实施条例；
3. 劳动法；
4. 劳动争议调解仲裁法；
5. 社会保险法；
6. 最高人民法院劳动争议司法解释（一）；
7. 最高人民法院劳动争议司法解释（二）。

再补充最低工资、工资支付、工伤、年休假等主题文件。

### 第二步：建立 metadata 和 manifest

在没有 metadata 的情况下，不要直接开始向量化。先确认每个文件的来源、版本、效力状态和哈希。

### 第三步：只导入 A 级法律并做检索 Smoke Test

先验证 Workflow 能否稳定找到正确的法律文档和条款，再导入 B 级案例。这样可以避免案例相似文本抢走法律原文的排名。

### 第四步：建立第一批规则卡片并人工复核

规则卡片必须引用已经入库的 A 级文档。没有法律引用的规则只能保持 `draft`，不能进入生产判断。

### 第五步：接入合同审查 Workflow

Workflow 的推荐顺序是：

```text
合同事实提取
  → 用户确认/补充
  → 信息完整性门禁
  → A 级法律检索
  → 确定性规则计算
  → 按需检索 B 级案例
  → 生成风险事实、等级和建议
  → 输出来源、待确认事项和免责声明
```

## 十、完成标准

只有满足以下条件，才算“劳动合同法律资料准备完成”，而不是简单地把文件放进文件夹：

- [ ] P0 法律资料全部有官方来源和版本元数据。
- [ ] 每份资料都通过效力状态和文本质量核验。
- [ ] A 级检索问题集达到预设 Hit@3 门槛，且引用条款可定位。
- [ ] 规则卡片全部绑定法律来源，至少经过一次人工复核。
- [ ] 5～10 份脱敏合同完成事实提取、确认和风险报告验收。
- [ ] 未确认事实不会产生确定性高风险结论。
- [ ] B 级案例只作补充说明，不能覆盖或替代 A 级法律依据。
- [ ] 报告明确声明：仅提供参考性信息，不替用户决定是否签署，不构成律师意见或责任担保。

## 十一、你现在可以立即做的事情

先不要收集海量案例。当前最有效的动作是：

1. 按“第九节第一步”下载 7 份 P0 法律资料；
2. 保留原始文件，不要改写原文；
3. 将每份文件的来源 URL、日期、效力状态和 SHA-256 填入 metadata；
4. 先不要上传真实劳动合同作为法律资料；
5. 把资料放到 `data/legal/labor_contract/raw/a_level/`，完成后再进入清洗、切分和导入步骤。

这批资料准备好后，就可以开始编写合同审查 Workflow 的第一个可运行纵向切片。
